Feedback & overlays

Every user action needs feedback from the system: received, in progress, done, or needs confirmation. The seven patterns below cover the levels of feedback, from a dialog that blocks the whole interface to a short message that dismisses itself. The wrong level either interrupts the user without reason or lets them miss information.

Modal dialog

A dialog that blocks interaction with the rest of the page. A panel sits in the center of the screen. An overlay dims the content behind it, which stays inactive until the user completes or closes the dialog. Focus moves into the dialog, Tab cycles only through its controls, and Esc or a click on the overlay closes it. Focus then returns to the button that opened it. Select “Invite member” to open the dialog.

Invite to project

Invitees receive an email and can see every task in “Launch 2.0”.

Use whenthe user must finish a short, self-contained task before continuing: filling in one to three fields, making one important choice, or confirming an action that cannot be undone. The break from context is intentional.

Avoid whenthe content is long or must be compared with the page behind it (use a drawer), the message is informational only (use a toast), or the dialog would open without a user action. Do not stack one modal on another.

In production, open the dialog with dialog.showModal(): the browser provides the focus trap, Esc, ::backdrop and an inert page. This demo uses show() + inert + a scripted Tab trap so the dialog stays inside the demo frame instead of covering the page.

Drawer / Side sheet

A panel that slides in from the edge of the screen. A drawer spans the full height of the viewport, slides in from the right and holds the details or edit form for the selected item. The list behind it stays visible. Select a task name, change its status and save; press Esc or tap outside the drawer to close it.

Task details

Use whenthe user views or edits one item while the list stays in sight (email, tasks, orders), and for filters with many options, shopping carts and mobile navigation menus. A drawer offers more space than a modal and keeps more context than a page change.

Avoid whenthe content is a flow large enough for its own page (it needs a shareable link and Back button support), or the question is short (use a modal). Do not open a drawer from inside a drawer.

Prompt tip: state whether you want a “modal side sheet” (overlay, focus trap) or a “non-modal / push drawer” (pushes the content aside, the page behind stays interactive). These are different behaviors.

Toast / Snackbar

A short message that dismisses itself after a few seconds. A toast appears in a corner of the screen after an action completes. It does not block interaction and hides after a few seconds. With an Undo button, delete and archive actions can run immediately without a confirmation step. Archive a few messages, then select Undo or press Z; hover over or touch and hold a toast to pause its timer.

Inbox 4 messages

    Use whenreporting the result of an action that needs no response: “Saved”, “Sent”, “Archived · Undo”. One line, at most one action, visible for 4–8 seconds, with the timer paused on hover or focus.

    Avoid whenreporting an error the user must fix (place the error next to its source), showing information the user must read, or offering an action with no other entry point: a dismissed toast cannot be recalled. Do not stack more than three toasts.

    Prompt tip: write “toast with Undo action, pauses on hover/focus, announced via aria-live polite, does not steal focus” so the AI does not build a toast that takes focus or stays silent to screen readers.

    Tooltip

    A short label that appears on hover or focus. A tooltip names a control and its keyboard shortcut, and is most useful on icon-only buttons. It appears after a short delay on hover and immediately on keyboard focus, switches without delay when the pointer moves to an adjacent button, and hides on Esc. Hover, focus or tap the toolbar icons and the i icon.

    Popover

    An interactive floating panel that opens on click. Unlike a tooltip, a popover opens on click and can contain buttons, checkboxes and links. A click outside or Esc closes it, and opening one popover closes any other. Open “Filter”, choose options and select Apply; open “Share” to copy the link.

      Confirmation dialog

      Progress indicator

      Shows that the system is working and how long it will take. Determinate: a bar or ring fills to 100%, with a percentage or the time remaining. Indeterminate: a moving stripe or spinner shows that work is in progress when the duration is unknown. A spinner suits a short wait inside a button; a progress bar suits a long task. Select the buttons to run each indicator again.

      Use whena wait exceeds about 1 second. Under 1 second: no indicator. 1–3 seconds: an inline spinner. Over 3 seconds, or when progress is measurable (upload, export, install): a determinate bar with a percentage and a Cancel button. If progress cannot be measured yet, start indeterminate and switch to determinate once data is available.

      Avoid whenloading content with a known layout (use a skeleton screen), or when the bar does not reflect real progress, for example one that reaches 99% and stalls: users lose trust at once. A full-screen spinner that covers the page is the weakest option.
